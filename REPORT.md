## Architecture

The system is one strict TypeScript package with two processes during a demo: a minimal Express target and an automation CLI. The synthetic target deliberately resembles a legacy back-office web app: server-rendered pages, tables, full-page navigation, stable operator language, and no test IDs. It offers deterministic fixtures for success, missing member, one transient load, permission denial, and a supervisor interstitial. There is no database, login system, queue, service mesh, or operator dashboard.

Two seams carry the design. `ModelClient` proposes one discovery action from a compact value-redacted semantic observation plus a screenshot only while that screenshot is safe to share, and discovery can explicitly select the OpenAI Responses API, Codex CLI, or Claude Code CLI transport. An unbound sensitive desired output switches the provider view to opaque page state and a page-wide screenshot mask because no generic adapter can yet identify an unknown value safely. `SurfaceSession` observes, locates, acts, reads, checks conditions, and preserves a live session. CLI transports use provider-owned authentication, bounded non-interactive execution, and schema validation; they do not persist provider sessions or receive sensitive invocation values in arguments. Replay accepts only a validated artifact, values, policy, surface, evidence writer, and optional operator; a test asserts that it has no model or transport import.

The order is intentional: policy validates, the resolved element is retained, ownership is re-checked, the surface acts within its remaining deadline, runtime state is classified, then the replay engine evaluates the checkpoint. That ordering lets “member not found” remain a business result and a transient page enter bounded recovery instead of being flattened into “heading missing.” Evidence is append-only JSONL plus sanitized surface snapshots and masked screenshots. The target is local because it gives repeatable exceptional states without third-party terms, rate limits, credentials, or drift.

## Artifact schema

The v1 JSON artifact is an agent-invocable contract rather than a model transcript. It has an explicit schema and capability version; identity, description, and maximum risk; compatibility metadata; typed input and output definitions; ordered steps; business-outcome rules; output bindings; a final success condition; and narrow discovery provenance. Scalar outputs are restricted to stable labels or bounded relative leaf hints rather than arbitrary CSS containers; literal outputs require an explicit matching constant contract; field-aware construction rejects raw or encoded invocation values in executable structural fields; and each scalar source is checked against its own live extracted output and rejected if it is broad, structured, or oversized.

Steps form a closed declarative union: navigate, click, fill, select, read, wait, and assert. Values are literals or named invocation inputs. Conditions are visible, hidden, URL, text, value, and explicit boolean composition. No JavaScript, shell, function, loop, or arbitrary branch can be serialized. Zod rejects unknown keys, unknown discriminants, duplicate step IDs, missing output bindings, and references to undeclared inputs.

Each control stores human language, a robustness explanation, exact expected cardinality, and candidates attempted in recorded order. Accessible role or label comes first; visible text, relative landmark, CSS, and coordinate descriptions remain available for less semantic surfaces. Zero matches stop. Multiple matches stop. The engine never selects the first of several ambiguous controls. Typed output bindings read review values through the same controls and built-in scalar parsers. Sensitive metadata drives redaction rather than changing the business shape returned to the in-process caller.

## Determinism & error handling

Replay validates artifact and inputs, intersects artifact origins with an independently configured origin policy, navigates to the entry point, and checks route and required landmarks before typing. It executes the stored sequence with fixed locator order and exact cardinality. Every material action can carry a postcondition. The checked-in reference artifact uses a composite review URL, heading, confirm-control, product, and nickname condition. A genuinely discovered artifact owns the model's verified declarative condition; its canonical receipt uses the unique `Ready for review` heading and then resolves and parses every declared typed output from that live surface. Route policy, declared step risk, and an independent blocked-control pattern prevent confirmation from being pressed. The demo server independently counts confirmation requests, and evidence generation asserts zero.

The public result separates success with typed outputs, expected business outcome, and normalized failure. Failure categories distinguish recovery exhaustion, hard application or surface failure, policy, and invalid artifact. The missing-member detector runs before the search checkpoint. The delayed-member fixture exposes `TRANSIENT_LOAD_TIMEOUT`; its artifact rule permits at most two model-free reload attempts. Permission denial stops with its code, step, expected or observed context, JSONL events, and a masked screenshot. Raw Playwright stacks and raw scalar values in parse errors are not part of the caller or persistence contract. Discovery transport failures are also normalized without persisting provider stderr or raw transcripts.

Discovery is separately bounded by step count, one abort-aware wall-clock deadline spanning browser and human operations, repeated proposal count, schema validation, policy, verified completion, input-independence validation, and live extraction of every declared output. Deadline expiry aborts the active operation and returns without waiting forever for hung work or cleanup; late browser, context, and page creation is closed. Each provider call receives only the remaining wall-time budget; an optional adapter override may narrow it but there is no undocumented default per-call ceiling. A model cannot declare success unless its declarative condition is true and its typed outputs resolve and parse according to the declared output types. The checked-in scripted run tests this same seam without claiming to be genuine. A genuine headed run using the explicitly selected, tool-disabled `codex-cli:gpt-5.6-luna` transport at xhigh produced `evidence/discovery-2026-08-16T23-12-04-329Z-7439cb4f/capability.v1.json`; its exact persisted file bytes have SHA-256 `6b579c4bb9e05826855f83ca91a18942af95c8f3cc466950e5d8e7322fd75a39` and replayed model-free with different inputs as `evidence/replay-2026-08-16T23-17-24-561Z-7432e8b8/` with zero confirmation action and zero model decisions. Discovery first verifies the live application identity and origin after entry. Each completion records a concrete external-process receipt from a module-registered adapter and runner: process ID, executable, argument and stdin digests, exit result, output source, actual schema-validation result, and proposal digest. Discovery completion and replay start/completion link that same persisted-file-byte SHA-256. Both streams record the independent configured origin and blocked-control policy. The sensitive member input is absent from persisted evidence.

## Heterogeneity & multi-tenant

The artifact records business intent and abstract controls; `SurfaceSession` implements perception and action. A legacy web adapter can map role, label, text, relative, CSS, frame path, or recorded coordinates to DOM, accessibility, OCR, or visual targeting without changing typed inputs, outcomes, or success conditions. A desktop adapter would map the same control vocabulary to UI Automation or accessibility nodes and screen coordinates. The current baseline executes web controls only and fails clearly for a recorded frame path rather than pretending desktop or hostile-frame support exists.

Compatibility metadata is fail-closed: surface kind, app family, optional variant, allowed origins, entry route, and required landmarks must match before business actions. At scale, one reviewed base capability would belong to a vendor-family/version range. Tenant variants could supply narrow, reviewable control-candidate or route overrides that only specialize the base; they could not broaden risk or origin policy. Preflight landmarks and post-action checkpoints act as drift sensors. A missing or ambiguous landmark, unsupported version, changed outcome, or failed checkpoint stops replay and routes review instead of guessing. Successful tenant-specific discoveries would become proposed versioned overrides, not silent mutations of the shared artifact.

## Escalation & handoff

Runtime intervention is modeled as ownership, not a fresh browser launch. The coordinator moves `automation → none/waiting → human → none/resuming → automation`. All automated action entry points re-check ownership immediately before acting. The intervention file carries the capability or goal, current step, stop reason, sanitized visible state, evidence paths, resume condition, and surface-session identifier.

The minimal operator surface is a headed browser plus CLI prompt. For the supervisor fixture, the person acts in the already-open page and explicitly returns control. The coordinator records a sanitized human-action description, re-evaluates the declared “Prepare new sub-account” resume heading in that same session, and resumes only if it is true. Tests also use a scripted operator at the same seam and verify event ordering and one unchanged session ID. Human actions are evidence, never inserted into deterministic capability steps.

The same coordinator also handles a model-declared discovery `stuck` state when an operator is configured: the proposal supplies a declarative resume condition, the person acts in the current surface, and discovery resumes only after verification. The person-operated `M-7000` receipt is preserved under `evidence/replay-2026-08-16T23-17-36-117Z-37f35130/`. Its current-source event stream records trusted person-operated CLI mode on a headed surface, transfer to human control, the person's sanitized CLI-reported action description `Clicked "Supervisor verified"`, return to automation with the same surface-session ID, independently verified resume state, successful review output, the exact discovered-file-byte digest, and no confirmation action. The receipt does not independently instrument the person's click.

## Safety

Configured policy allowlists exact local origins, narrow route patterns, action kinds, step and time bounds, and permitted risk classes. The CLI defaults to the known local synthetic origin and accepts a separate operator-supplied origin override; it never derives that authority from an artifact. Artifact permissions can only narrow those settings. Initial navigation, model-proposed actions, replay actions, click-triggered document navigation, and pre-frame popup navigation pass through policy. Additional pages are closed and rejected. The `/confirm` route is absent from the route allowlist, its step is classified irreversible, and its resolved DOM control text is independently blocked immediately before interaction even when artifact risk and locator metadata are dishonest.

Only deterministic synthetic fixtures are used. API keys remain provider-owned process or CLI authentication values. Browser cookies, credentials, prompts, hidden reasoning, and raw transcripts are not written. The CLI adapters pass prompts through stdin, redact raw and URL-encoded representations of declared sensitive values from provider-bound semantic state, withhold screenshots whenever a desired output is sensitive or sensitive input may have reached the page, keep sensitive invocation values out of argv, and remove temporary schema/output files after each model call. Discovery and replay derive sensitive fields and values inside the engine, so direct API callers receive the same persistence boundary. The evidence writer validates schema-definition exemptions before preserving them and redacts secret-shaped keys, declared sensitive input and output fields, sensitive values embedded inside longer strings, encoded sensitive values, and long account-like numbers before any JSON or text write. Screenshot masking follows sensitive values into differently named controls and text nodes. Validated replay output targets are masked directly; unbound sensitive discovery outputs force opaque page state and a page-wide screenshot mask instead of trusting label heuristics. The aggregate manifest passes through the same field sanitizer. Evidence names actor, reason, step, ownership, result, and repository-relative diagnostic paths without persisting the image data URL.

This is a demonstration boundary, not production security. A real deployment still needs authenticated operators, credential brokering, tenant authorization, encrypted retention, immutable audit storage, model and artifact approval governance, and adversarial testing.

## Cuts

The implementation stops at the required thin vertical slice. It does not create an account, contact a bank, store real financial data, expose a capability catalog API, auto-repair replay with a model, route or fall back between providers, implement desktop execution, maintain a tenant registry, stream a browser, or build production authentication and infrastructure. It also avoids optional assignment stretch goals.

With more time, the first additions would be independent artifact approval and signing, a real authenticated operator channel, accessibility/OCR desktop adapters behind `SurfaceSession`, a vendor-family compatibility registry with narrow tenant overrides, and stability telemetry across repeated approved replays. Those come after—not inside—the reviewed v1 capability and policy boundary.
